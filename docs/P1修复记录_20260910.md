**运行时新发现并当场修复的 1 个 bug（值得记录）**

新增的 RCON 认证校验首版把包头 `type` 读成了**偏移 4**（实际协议布局是 `length(0) + requestId(4) + type(8)`），于是把正常握手（type=2）读成 0 → guardian 每 15s 写一条 `RCON auth FAILED`，RCON 全部失效（健康判定仍正常，因为 V54 之后以心跳为准）。修正为偏移 8，并把认证判定改成"只有收到 -1 才算失败、最多读 3 个包兜底"，重启 guardian 后 `guardian.state = healthy (rcon=ok hb_age=0s)` ✅。教训：**校验逻辑本身也要能被验证**——这次是靠"部署后立刻看日志"在 5 分钟内发现的。

## 6. 决策质量修复（2026-09-10 17:30 ~ 17:50，接 P1 之后）

P1 部署后从现场数据发现：修复方向对了，但**真正的瓶颈是"决策被大量拒绝 + 策略坍缩"**，而不是模型结构。本节记录定位过程与三项修复。

### 6.1 定位：instructor 自己的指标 + 现场逐动作归因

`course.json`（上一轮 instructor 输出，346 万步）里写着：

```
rejected_rate = 0.9665        ← 96.65% 的决策被执行器拒绝
kill_rate     = 0.00084       ← 0.084%
weakness      = ["rejected_high", "kill_low"]
```

现场按动作归因（trace dump `D` 行的 `action` × `exec=`）得到精确构成：

| 动作 | 次数 | EXECUTED | REJECTED_BUSY | 说明 |
|---|---|---|---|---|
| 0 idle | 269 | 0 | **268** | **等待本身被拒**（`canExecute` 对 IDLE 也走 inaction 门控） |
| 8 roll | 231 | 2 | 229 | 40t 冷却中仍被提供 → 选了必被拒 |
| 5 parry | 123 | 123 | 0 | 正常 |
| 7 dodge | 90 | 0 | 90 | 耐力不足仍被提供 |
| 9 cycle_melee | 57 | 0 | 57 | 换装冷却中仍被提供 |
| 62 dodge_step | 16 | 0 | 16 | 冷却/耐力未纳入可用性 |

即：**`RlActionExecutor.available()` 的契约被违反**（其 javadoc 明确要求"只返回当前确实可用的行动"），
`GenericCombatExecutor` 与 `DefenseSkillExecutor` 却无条件提供全部槽位。而这些"提供了却执行不了"的步
**仍按模型选择的动作进入 BC/AWR**（P5.7 的拒绝标签改写只覆盖技能槽，generic 动作 0..10 不受影响）
→ 训练目标里混入大量无效动作，`rejected_high` 自我强化。

### 6.2 三项修复

| 修复 | 内容 | 位置 |
|---|---|---|
| ① 动作窗口掩码 | 决策点若"动作窗口关闭"（自身在不可打断动画中），只保留 idle、紧急动作（roll/dodge/parry）与防守技能槽，其余置零；**ε-greedy 也只在可执行集合内探索** | `RlBrain`（`masked[]` + `isUrgentSlot/isIdleSlot`） |
| ② 可用性契约 | `GenericCombatExecutor.available()` 按当前状态返回槽位，不可用者以 **null 占位**（必须占位：固定段按顺序写入，跳过会破坏动作编号契约）；IDLE 恒可用且 `canExecute` 对 IDLE 直接放行；`DefenseSkillExecutor` 同样处理 | `GenericCombatExecutor`、`DefenseSkillExecutor`、`CombatActions.canDodge/canRoll/canCycleWeapon/canParry/canBlock` |
| ③ 防守冷却 + 距离惩罚豁免 + 弱标靶 | 弹反/格挡加 15t 冷却（此前无冷却 → "原地弹反"吸收态）；距离惩罚豁免"无目标/被击倒/动作中"三种不可控处境（此前 p50 长期停在封顶 −16）；封顶值改可配 `prox_penalty_max`；竞技场切到弱标靶单目标 `swordsman_herobrine`（`arena_overrides.entity` 此前被静默忽略，本次一并实现） | `CombatActions`、`RlBrain`、`RlConfig`、`AutoArena`、`course.json`/`arena.properties` |

**为什么 ③ 的"原地弹反"必须修**：弹反一度占决策的 ~100%——它既有冷却豁免、又在 `applyDiversityReward`
里被当作"多样性重置"（每次弹反清空反滥用窗口），于是"一直弹反"既不触发衰减、也不产生任何奖励
（无命中/无受伤/距离惩罚被豁免）→ **奖励恒 0 的吸收态，没有任何梯度**。加冷却后同一动作最多每 3 个决策
一次，反滥用窗口（50 决策 >8 次）重新生效，策略被迫在防守之外做进攻选择。
