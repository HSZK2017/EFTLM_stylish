# 技术报告：EFTLM-Stylish 全自动战斗 AI 架构重写方案

**报告日期**：2026-08-26
**分析对象**：`E:\program\JAVA\EFTLM-example`（eftlm_stylish 模组本体）＋ `E:\program\JAVA\EpicFight_TouhouLittleMaid`（EFTLM 基础模组）＋ `E:\program\JAVA\epic mod suitable\参考\Avalon`（Epic Fight: Avalon 动作帧模组源码，EFTLM 直接依赖，对应 `epic_fight_avalon-20.12.6.4.jar`）＋ `prod_server` 训练/生产服务器
**报告目的**：基于现有"传感器 → 权重计算 → 威胁排序 → RL 决策 → 事件总线 → 执行状态机 → 反馈闭环"架构的**源码事实**，分析其在生产环境中无法正确应对敌方单位的根因（对照实测发现的 5 项复杂限制），并给出**完整的架构重写方案**与落地路线图。

## 结论先行（TL;DR）

现有架构在"封闭竞技场 vs 单一 Boss"的简化环境下可以收敛（已迭代至 v46、采集 1.5 万+ 条轨迹），但它有三个**结构性缺陷**，导致进入真实战场后必然失效：

1. **决策与动画时序脱节**：模型不知道"自己当前正在播放什么动画、还有多少帧、哪些帧可打断"——而生产环境的动作模组绝大多数动画帧不可打断。模型输出的攻击在动作中会被执行器直接拒绝（`REJECTED_BUSY`），5 tick 决策节拍（250 ms）对前摇规避来说太慢；
2. **状态没有"时间"与"空间"**：32 维状态是瞬时标量，没有历史帧、没有弹道实体、没有地形/障碍/危险区、没有己方 BUFF/DEBUFF、没有"目标脱锁后的预期位置"。维吉尔式闪现、放风筝、造障碍、流水、钩爪全部落在状态盲区；
3. **训练是"离线清洗 + 手工奖励塑形"**：无价值函数、无在线交互、无对手课程，模型学到的是奖励工程的产物（近战熵、远程衰减、贴脸惩罚……），而不是"读招、择时、应对"的战斗技能。

**重写方案一句话**：把单层 RL 决策改为 **反应层（每 tick 规则+微型模型，兜底生存）→ 战术层（RL 选技能宏）→ 战略层（低频选武器/目标/资源）** 的三层结构；给所有动作建立 **Commitment（提交/活性/取消点/可打断性）元数据**；把感知升级为 **目标记忆（脱锁外推）+ 弹道感知 + 自状态（buff/武器库/动画承诺）+ 空间栅格**；训练改为 **在线 RL（带 critic）+ 影子评估 + 脚本化对手课程**。

## 一、现状架构盘点（源码事实）

### 1.1 决策闭环总览

当前闭环（与设计意图一致，源码实现）：

```
[TargetTracker 每帧扫描 32 格]
        │ 维护 TrackedTarget（位置/血量/护甲/phase/攻击中/威胁分）
        ▼
[RlBrain.tick 每 5 tick] ──→ [RlState.collect 32 维归一化]
        │                      ├ 0..17  单目标基础态势 + 执行反馈(16/17)
        │                      └ 18..31 TargetTracker 多目标聚合特征(14 维)
        ▼
[RlActionRegistry.buildLayout 64 槽 = 11 通用 + 53 技能槽]
        │ 空槽 = 无效（掩码置零）；ε-greedy(0.08) 探索
        ▼
[RlModel.forward MLP 32→64→64→64 + Softmax]（16/18 维旧模型兼容截取）
        │ argMax
        ▼
[硬约束修正]：被击倒→强制翻滚；持近战选远程→回退近战；无目标→降级待机
        ▼
[Forge EVENT_BUS post(RlActEvent)] ──→ [RlActionRegistry.dispatch]
        │                                     ▼
        │                   [GenericCombatExecutor] 通用 0..10（攻击/大招/JC/弹反/格挡/闪避/翻滚/切武器/远程）
        │                   [EfnSkillExecutor]       技能池（skills.json 目录 → 当前主手可用技能动画）
        │                   [DefenseSkillExecutor]   dodge_step / blade_clash（技能池末尾）
        ▼
[RlExecResult → StyleState LAST_EXEC_OK / LAST_EXEC_REJECTED → 状态 s[16]/s[17] 闭环]
        │
[RlDataRecorder 轨迹（state, action, reward）→ trajectories/*.bin]
        │
[iterate.py 每 6h：快照→清洗→train_ppo.py→部署→RCON /rl reload]
```

### 1.6 防守/闪避逻辑参考实现分析（三源交叉）

分析对象：① EFTLM 开源技能书"灵动步伐"（`EF/Skill/Dodge/Step.java`）与"刀光剑影"（`EF/Skill/Guard/BladeClash.java`）；② EpicFight 内核 `DodgeAnimation`；③ epicmoonmod 1.2.1（`epicmoon_decompiled/`，Vineflower 反编译）"加速弹"武器=瓦伦西娜双刀（`VALENCINA_DUAL_SWORDS`）的**预知之眼自动闪避系统**。

#### 1.6.1 灵动步伐（Step）—— 现成的前摇反应模板

| 事实 | 源码证据（EFTLM 开源） | 意义 |
|---|---|---|
| 触发条件 | 每 tick 读目标 `getEntityState().getLevel()`，`Phase>0 && Phase<3`（前摇+攻击阶段）即闪避 | 与 3.3 反应层"前摇规避"同构，且**已实现**（当前 `CombatActions.dodgeFromAttack` 即移植自它） |
| **方向判定算法** | `attackDir`（目标 yaw 朝向）与 `toMaid`（目标→女仆）做 `dot`/`crossY`：`\|dot\|>\|crossY\|` → 迎面攻击向后闪/背身攻击向前闪；否则左右（`crossY>0` → 右闪避动画） | 反应层"朝攻击反方向闪避"的精确算法，直接复用 |
| 冷却/资源 | 10 tick 冷却；耐力消耗 `WEIGHT×0.1` | 闪避资源预算：10t 冷却内不重复闪避 |
| **特殊动画保护** | `EFNCompat.isSpecialAnimation(patch)` 为真 → 不闪避 | 防止闪避打断特殊技能动画——**正是 3.3"打断保护"的参考实现** |

#### 1.6.2 刀光剑影（BladeClash）—— 攻击中拼刀（与窗口制弹反互补）

| 事实 | 源码证据 | 意义 |
|---|---|---|
| 触发条件 | 女仆**攻击中**（`phaseLevel 1~2`）且被**正面可格挡**攻击命中（`MaidAttackEvent`） | 与当前窗口制（弹反 10t/格挡 20t）互补：**攻击动画期间自动拼刀**，攻击中也能防守 |
| 拼刀消耗 | 耐力 `penalty × impact`；`penalty` 每次拼刀 +0.1，40 tick 恢复；`impact` 来自 `EpicFightDamageSource.calculateImpact()` | 连续拼刀成本递增 = 天然防滥用；**冲击力是拼刀可行性参数** |
| 效果 | 双方击退（`knockback = 0.1 + min(impact×0.1, 1.0)`）、CLASH 音效/粒子、**全额取消伤害** | 攻击中防守的完整实现，奖励函数可直接挂钩"拼刀成功" |

#### 1.6.3 EpicFight DodgeAnimation 内核语义（开源）

| 参数 | 语义 | 意义 |
|---|---|---|
| `delayTime`（DUAL_DODGE=0.6F，默认 10F） | 保护窗：`0..delayTime` 内 INACTION + MOVEMENT_LOCKED + CAN_BASIC_ATTACK=false | 闪避窗口帧数 = 决策时序基准（如 0.6F≈12tick 保护） |
| `width/height`（DUAL_DODGE=0.8） | **闪避期间实体碰撞盒缩放**（`RESIZE_BOUNDING_BOX` tick 事件） | 碰撞盒缩小 → 敌方范围判定更难命中；感知层可读取当前碰撞盒做威胁评估 |

#### 1.6.5 对反应层闪避子系统的直接结论

1. **伤害源分类表**（新增 `DamageClass`）：`DODGEABLE`（物理近战/可闪避弹道）→ 闪避；`BLOCKABLE`（可格挡）→ 格挡/拼刀；`PARRYABLE`（正面近战可弹反）→ 弹反；`UNBLOCKABLE`（`BYPASS_DODGE`/魔法/爆炸/无视护甲）→ **闪避/格挡均无效，只能位移规避或硬吃**——决策顺序：UNBLOCKABLE（位移）> PARRYABLE（弹反）> DODGEABLE（闪避）> BLOCKABLE（格挡）；
2. **阈值制资源化闪避**：闪避资源池（耐力或独立"预知之眼式"资源），`结算伤害 ≤ 阈值` 的常规攻击自动闪避（每 tick 判定、无决策延迟），高威胁伤害保留资源做位移规避；
3. **攻击中拼刀兜底**：不可打断帧期间被正面可格挡攻击 → 自动拼刀（刀光剑影逻辑），保证"动画中也有防守"；
4. **闪避成功反馈**：女仆（MobPatch）无玩家 `DodgeSuccessEvent`——在 `ATTACK_RESULT=MISSED` 挂钩自建事件：闪避成功 → 奖励 + 派生宏机会 + 加速类状态（借鉴加速未来，可映射为华丽度/技能层数增益）；
5. **碰撞盒读取**：闪避窗口内碰撞盒缩放 → 威胁评估（3.2.5）与 AOE 规避判定使用当前实际碰撞盒。

### 1.7 现状架构对 5 项生产限制的覆盖情况

| 限制 | 现状覆盖 | 缺口 |
|---|---|---|
| ① 动作大多不可打断 | 只有 roll/dodge/parry 可在动作中执行；被击倒强制翻滚；箭矢反应（仅 `AbstractArrow`） | **没有动画帧/剩余时长/取消点信息**；攻击类动作在动作中一律被拒，模型无法择时 |
| ② 闪现/远程放风筝/脱锁 | 32 格扫描 + 2 秒过期；锁定加固（`lockHighThreatTarget`）；距离 4.5 格切远程的**规则**兜底 | 脱锁即丢（无预期位置外推）；技能弹道（幻影剑/次元斩）既不是目标实体也不是箭矢，**完全不可见**；放风筝应对是规则不是策略 |
| ③ BUFF/DEBUFF、武器库、多派生 | 己方自动喝增益药水（规则）；每 6 次命中/连段结束轮换武器（规则）；flair 评分在状态 s[4] | 状态里**没有己方 buff/debuff**；模型无法表达"切到哪把武器、为什么"；武器切换的评分价值只靠熵奖励间接建模；**技能槽位漂移**使跨武器序列不可学 |
| ④ 障碍/流水/击退/钩爪 | 无 | 状态零空间信息（只有距离标量）；移动完全交给 TLM 导航 + EpicFight AI；被击退/被拉近无事件通道 |
| ⑤ 霸体/强控 | 被击倒→翻滚（硬约束）+ 倒地惩罚 -30；弹反/格挡窗口 | 无"敌方技能前摇/活性/后摇"阶段识别（s[7] 只是 0/1）；无"跃起瞬间闪避"的时序能力；起身只有翻滚一种；**无目标霸体感知**（打了没硬直，模型不知道） |

## 二、生产失效根因分析

### 2.0 三个结构性根因

**根因 A：决策粒度与动画时序脱节（限制①⑤的共同来源）**
- RL 每 5 tick 决策一次，但执行器要求"上一动画结束才播放下一个"（`inaction()` 门控）。于是：模型在动画中输出的攻击被拒（s[17]=1），输出的闪避虽然放行但动画本身有前摇；模型**既不知道当前动画还剩几帧，也不知道敌方攻击还有几帧落地**。
- 敌方前摇往往只有 5~10 帧（250~500 ms）。5 tick 决策 + 动画播放延迟 + 前摇检测缺失，使"在跃起那一刻闪避离开落地范围"在数学上不可能发生——它只能靠运气。
- 训练数据里 s[16]/s[17] 只是 0/1 两位，模型无法区分"忙（动画中）"与"无效（无资源/超距）"，反馈信息量不足。

**根因 B：状态没有时间与空间（限制②③④的共同来源）**
- 无历史帧：模型是纯瞬时 32 维 MLP，读不出"敌人正在朝我逼近/弹道正在飞行/我正处于后摇"这类时序事实；
- 无弹道实体：`reactToArrow` 只认 `AbstractArrow`，EFN 幻影剑、次元斩、剑气等技能弹道实体对感知层不可见；
- 无脱锁记忆：`TargetTracker` 40 tick 未扫到即删除——维吉尔闪现出 32 格后 AI 完全失明，连"他最后在哪、朝哪移动"都不知道；
- 无空间：障碍、流水、AOE 落地范围、击退向量、钩爪拉近，全部不在状态里；
- 己方 buff/debuff、武器库构成、每把武器的派生状态，全部不在状态里。

**根因 C：离线训练 + 手工奖励 = 学到奖励工程的产物（所有限制的放大器）**
- `train_ppo.py` 的"策略梯度"实际是 **GAE(baseline=0) 加权的行为克隆**（RW-BC），没有任何在线交互：模型永远在模仿"规则策略 + 旧模型"混合产出的轨迹，无法从自己的失败中学习；
- 奖励是 20+ 条手工塑形规则（熵奖励、远程衰减、贴脸惩罚、连击熔断……），模型的最优解是"最大化奖励工程"，而不是"打赢战斗"——这解释了为什么模型在竞技场（cage 8 格、单一 Boss）里看起来在进步，换到真实战场立即崩盘；
- 竞技场环境与生产分布差距巨大：虚空平台 + 世界边界 vs 真实地形；单一类型 Boss vs 任意怪物/玩家；无 buff 战 vs 满 buff 战。**分布偏移**没有被任何机制度量或补偿；
- 部署无门禁：`iterate.py` 训练完直接覆盖生产模型（v46 是第 46 次盲部署），没有影子评估、没有胜率/受击率门禁、没有自动回滚。

### 2.1 限制①：生产动作模组（类鬼泣）绝大多数动画帧不可打断

**现象**：模型在长连段/技能动画中收到"闪避/格挡"指令无法执行（被 `inaction()` 门控拒绝，或播放被覆盖），敌方攻击打过来只能硬吃；反过来，模型提交的长技能也无法在敌方前摇窗口内取消。

**根因**：
- 动作被建模为**不可观测的黑盒**：模型不知道当前动画的剩余帧数、可打断点（cancel window）、位移承诺（突进/升空）；
- `GenericCombatExecutor.canExecute` 的"非动作中才执行"纪律（当初为规避 EFN `LinkAnimation` NPE 竞态而设，见 `docs/EFN_NPE豁免技术报告_20260823.md`）把"择时"责任全部推给模型，但状态里没有任何时序信息可供择时；
- 5 tick 决策节拍使"每帧评估可打断性"不可能；
- **Avalon 源码里不可打断性是显式属性**（`AvalonAttackAnimation` 构造器 `CANCELABLE_MOVE=false`——注意 EpicFight 原版 `BasicAttackAnimation` 默认是 `true`，这是 Avalon/EFN 系的主动约定），且 `bindPhaseState` 已把帧区间映射为 `EntityState`（INACTION / MOVEMENT_LOCKED / CAN_BASIC_ATTACK / PHASE_LEVEL 1|2|3）——这些承诺信息运行时唾手可得，**现状只读取了 `getLevel()` 一个维度**（`RlState` s[7]），等于把现成的帧级状态谱全部扔掉。

**重写要求**：
1. 为每个动作建立 **Commitment 模型**（见 3.6）：`{提交点, 活性窗口, 取消点, 后摇, 可打断集合, 位移承诺, 射程, 硬直需求}`；
2. 决策层看到的是**承诺状态**（"当前动画 2 帧后到取消点"），而不是黑盒动画；
3. 反应层**每 tick** 评估紧急行动（闪避/格挡/起身），不依赖 5 tick 决策节拍。

### 2.2 限制②：维吉尔式闪现 + 次元斩/幻影剑远程放风筝 + 脱锁

**现象**：敌人闪现出扫描范围 → 40 tick 后从目标列表删除 → AI 失明发呆；敌人远程放风筝 → 距离武器切换规则（4.5 格切远程）是唯一应对，且 RL 决策里"远程"被 V18 硬约束限制（持近战选远程→回退近战）；次元斩/幻影剑等技能弹道无法感知，无法做出格挡/闪避/弹刀。

**根因**：
- 感知只认 `LivingEntity` 与 `AbstractArrow`；而 Avalon 弹道（`AvalonProjectileEntity extends Mob`，EFN 幻影剑等技能弹道）**会被 LivingEntity 扫描捕获、却被按"目标"而非"弹道"处理**——目标列表被弹道实体污染，同时弹道本身没有轨迹/ETA 感知；AOE 区域标记完全缺失；
- 目标跟踪无预测：脱锁 = 删除，而不是"记忆最后位置 + 速度外推 + 置信度衰减"；
- s[0] 无目标与远目标同值 1.0（V17 已发现但只做了"无目标降级待机"的补丁，没有解决"远目标"的表达问题）；
- 远程应对被塑形成"规则切换武器"，模型没有"保持距离/拉近距离/利用射程"的策略维度。

**重写要求**：
1. **目标记忆（Ghost Target）**：脱锁不删除，转为"预期位置 = 最后位置 + 速度外推"，置信度随时间衰减，重锁成本可计算（见 3.2.1）；
2. **弹道感知**：投射物统一抽象（箭矢/幻影剑/次元斩/剑气/魔法弹），含速度、剩余飞行时间（ETA）、预计落点、是否可格挡（见 3.2.2）；
3. 状态增加"最近目标武器类型/是否远程/放风筝意图"通道，把远程应对从规则升级为策略空间；
4. 锁定优先级：威胁分中加入"远程威胁"（弹道 ETA 短）与"控制风险"（有强控技能）。

### 2.3 限制③：BUFF/DEBUFF 与多武器库多派生，华丽切换是评分关键

**现象**：双方都有背包道具/战技/受击带来的 buff/debuff；武器库可随时切换，每把武器自带技能派生树（阎魔刀/贝奥武夫式）；华丽切换武器是评分关键，反之降分。当前 AI 的武器切换是规则轮换（每 6 次命中），与战局无关。

**根因**：
- 状态只有目标 `hasBuff` 1 位（s[25]），**己方 buff/debuff 完全缺失**——模型无法学会"等 buff 窗口输出/先驱散再打/被减速时别突进"；
- 武器库不在状态里：模型不知道背包里有什么武器、当前武器是什么、切换冷却还剩多久、下一把的派生能力是什么；`ACT_CYCLE_MELEE` 是一个无参数动作号，模型无法表达"切到远程切到阎魔刀切到拳套"；
- **槽位漂移（最严重）**：技能槽 11..63 按"当前主手可用技能"顺序填充，换武器后同一索引指向不同技能。训练标签是索引——同一标签在不同武器下语义不同，跨武器序列被训练数据污染（`relabel.py` 只能把 11..63 整体当作"近战/特技"清洗，无法解决）；
- 评分（flair）只在状态 s[4] 出现，模型不知道"刚才换武器涨了多少分/连续同一把武器在掉分"——DMC 式风格系统的"切换价值"没有被建模为可学习的奖励信号。

**重写要求**：
1. 状态增加己方 buff/debuff 摘要（类型桶：输出/机动/防御/控制免疫/持续伤害）与武器库清单（当前武器 id、候选武器 id、每把的派生可用性）；
2. **动作空间分解为（武器选择 × 武器内技能）两层**，或技能槽按**稳定技能 id** 排序（模型输出槽位语义永不漂移），见 3.4.2；
3. 评分机制显式进奖励：切换后接技能/连段的"切换连携"给结构化奖励，长期同一武器/重复动作按风格规则扣分——但用**可解释的稀疏规则**替代现在的熵+滥用塑形（后者把风格变成了概率分布约束，见 4.2）。

### 2.4 限制④：障碍、流水、击退、钩爪（空间控制）

**现象**：敌方造出短暂不可通过的障碍或流水 → AI 只会直线寻路被卡；击退把 AI 推开 → AI 重新寻路，没有"位移事件"感知；鱼钩类装备把 AI 拉近 → AI 措手不及。

**根因**：
- 状态零空间信息：没有局部栅格、没有可达性、没有流体/障碍/危险区标记；
- 移动完全由 TLM 导航 + EpicFight AI 驱动，RL 只有"切武器/攻击/闪避"等瞬时动作号，**没有移动意图通道**（"绕行到侧翼/撤出流水/AOE 范围"）；
- 击退/拉近是**位移事件**，当前既不在状态（下一次采集时距离已经变了）也没有事件通道，模型无法把"我被拉近"与"敌人要打我"关联起来。

**重写要求**：
1. **空间感知模块**：以女仆为中心的局部栅格（半径 ~16 格），编码可达性（障碍/流水/岩浆）、危险区（AOE 落地范围/弹道路径）、击退向量；压缩为固定维特征（方向桶 + 距离桶）喂给战术层，另提供"可达性"给战略层/导航；
2. 位移事件通道：被击退/被拉近/被传送 → 事件总线事件 + 状态标记（"最近 10 tick 被强制位移"），反应层可立即应对（拉近→格挡/闪避；击退→受控状态下不追）；
3. 导航升级：脱离流水/障碍用路径点重新规划，而不是直线寻路。

### 2.5 限制⑤：霸体与强控（跳劈落地范围倒地、起身闪避）

**现象**：敌人霸体打不出硬直，AI 还在按"连段压制"策略输出被反打；敌人跃起下劈 → 范围倒地，AI 没有在跃起时刻闪避出范围的能力；倒地后只会翻滚起身，不知道可以起身闪避。

**根因**：
- 敌方技能阶段只有 0/1（s[7] attacking）与 phase/4（s[29]，仅最近目标）——**没有 WINDUP(前摇)/ACTIVE(活性)/RECOVERY(后摇) 三阶段**，"跃起那一刻"= WINDUP 早期，状态里没有；
- 倒地处理是硬编码 `knockDown() → rollRecovery()`，没有"受控状态机"（倒地 → 无敌帧 → 起身选择：起身闪避/起身格挡/延迟起身骗招）；
- 无霸体感知：目标被打是否产生硬直可以从**受击事件**观测（hitstun 时长），当前完全没采集，模型不知道"这刀下去对方会不会硬直"。

**重写要求**：
1. **敌方技能阶段状态机**：每个威胁目标维护 `{IDLE, WINDUP, ACTIVE, RECOVERY}` + 剩余帧 + 该技能的作用范围/类型（单体/横扫/AOE 落地）；WINDUP 起始帧是反应层的最高优先级输入（见 3.3.2）；
2. **受控状态机**：把"被击倒/被浮空/被拉近/被冰冻/被点燃"统一为控制状态层，每种控制状态带"恢复动作集 + 恢复时机"（起身闪避 vs 起身格挡由战术层选，反应层保证最迟恢复时限）；
3. **霸体感知**：从伤害事件学习目标硬直响应（命中后 hitstun 时长/是否中断动画），写入目标记忆；策略层据此选择"压制型 vs 弹反/后摇输出型"打法。

### 2.6 训练体系根因（补充）

| 问题 | 事实 | 后果 |
|---|---|---|
| 无 critic | `train_ppo.py` GAE baseline 恒 0 | 优势估计 = 折扣回报，方差极大，RW-BC 实际是"奖励加权克隆" |
| 纯离线 | 每轮只消费新轨迹，`--init` 续训 | 无法从失败纠正；ε-greedy 0.08 在真机上是随机破坏而非探索 |
| 动作索引漂移 | 64 槽 = 动态技能槽 | 跨武器标签污染（2.3） |
| 状态无时序 | 32 维瞬时向量 | 学不会弹道/前摇/承诺类时序事实 |
| 环境单一 | 虚空平台 + annoyingvillagers 系 Boss + 8~20 格 cage | 严重过拟合，生产分布偏移无度量 |
| 部署无门禁 | 训练完直接覆盖 + `/rl reload` | v46 次盲部署，无回滚指标 |

## 三、重写架构设计

### 3.0 设计原则

1. **分层决策**：反应层（生存）→ 战术层（技能选择）→ 战略层（武器/目标/资源）。越快的事用越简单越快的机制，RL 只负责它擅长的"择时与组合"；
2. **把"不可打断"作为先验建模，而不是让模型去撞**：所有动作带 Commitment 元数据，决策层永远知道"现在提交会怎样"；
3. **感知 = 状态 + 事件**：瞬时状态向量表达"是什么"，事件总线表达"刚才发生了什么"（被击退/被拉近/弹道生成/受控/霸体命中）；
4. **模型-规则混合**：反应层规则保证底线（永不发呆、永远能起身、永远会躲弹道），RL 在底线之上优化（打得更华丽、更聪明）；
5. **可验证部署**：影子评估 + 指标门禁 + 一键回滚，杜绝盲部署。

```
└──────┬──────────────────────────────────────────────────────────────────────────────────────────────┘
       │ 执行结果（EXECUTED / BUSY_IN_ANIM / IN_COMMIT_WINDOW / NO_RESOURCE / OUT_OF_RANGE）
       │ + 战斗事件（命中/受击/控制/弹反）→ 奖励信号 → 轨迹 → 训练闭环
```

### 3.2 感知层详细设计

#### 3.2.1 目标记忆 TargetMemory（解决脱锁）

```
TrackedTarget 扩展：
  ├─ 确定性信息：uuid / 类型 / 最后扫描到的 position / velocity（平滑估计）
  ├─ 状态：hp / 护甲 / 移动速度 / 霸体标志 / 硬直响应表（hitstun 时长）
  ├─ 技能状态机：currentSkill {id, phase: IDLE|WINDUP|ACTIVE|RECOVERY, phaseStartTick, range, type}
  ├─ 威胁分（多维，见 3.2.5）
  └─ 置信度 confidence ∈ [0,1]
       未脱锁：= 1
       脱锁后：每 tick 衰减（半衰期 ≈ 2 秒），位置 = 最后位置 + 速度外推
       幽灵目标（confidence 低）仍参与威胁评估，但标记"推测"，战略层决定是否追击
```

**敌方技能阶段的数据来源（分级，按敌方技术栈）**：
- **EpicFight patch 敌方**（EFN/WOM/DMC 系武器使用者、AV 系 Boss——AVNpc/HerobrineMob 均挂 EpicFight patch）：直接读 `patch.getEntityState().getLevel()`（1=前摇 2=攻击 3=后摇，官方语义）＋ 当前动画 `getPhaseByTime(elapsedTime)` 的 `preDelay/contact/end` 帧 → **WINDUP/ACTIVE/RECOVERY 无需建模**，level 1 即前摇窗口；
- **非标准动画敌方**（AV 系自研动画类 + tick 逻辑）：`EnemySkillDatabase` JSON（反编译 + 人工标注，见 1.5），按"技能 id → 前摇帧/判定范围/AOE 半径/后摇/控制类型"查询；**1.5 节已完成三个标靶（AngrySteve/Alex/Null）的第一轮反编译分析**，可直接落库：AngrySteve（霸体/爆发保护/方块格挡/珍珠反击）、Alex（钩枪/钓鱼竿/Jev/二阶段）、Null（飞行武器群/弹道免疫/概率弹反/附身），通用机制（处决/放墙/岩浆/读招）见 1.5.4；标注数据经竞技场实测校准（观测到起跳→落地的时间差与标注值比对）；

- 删除条件从"40 tick 未扫到"改为"置信度低于阈值 **且** 无弹道/无近期活动线索"；
- 重锁：真实扫描命中幽灵目标 → 置信度回 1，并记"脱锁事件"（可作训练特征：目标闪现频率）。
- **锁定范围**：目标记忆不受 32 格扫描半径限制（记忆≠扫描），远距离放风筝的敌人始终有"预期位置"，AI 可以追向预测点而不是失明。

#### 3.2.2 弹道感知 ProjectilePerception（解决次元斩/幻影剑）

统一投射物抽象（替换现在只认 `AbstractArrow` 的 `reactToArrow`）：

```
Projectile {
  kind: ARROW | SUMMONED_SWORD | SLASH_BEAM | MAGIC_BOLT | AOE_MARKER ...
  position, velocity, acceleration
  eta（预计到达女仆时间）, predictedImpactPoint
  blockable: 可格挡? 可弹反? 需要闪避? 霸体判定?
  owner（发射者 → 关联到目标记忆）
}
```

- 生成来源：`AbstractArrow`、`AbstractHurtingProjectile`、`AvalonProjectileEntity` 及其子类（EFN 幻影剑等——**extends Mob，必须先于目标扫描做 instanceof 分流，否则被 `TargetTracker` 误加进攻击目标列表**）、AOE 区域标记（技能落地范围以空间区域登记，如跳劈落点）；
- 事件：弹道生成 → 事件总线（反应层在 ETA < 阈值时立即决策，不等 5 tick）；
- 状态：态势向量加入"最近弹道 ETA/方向桶/可格挡性"（压缩 3~5 维）。

#### 3.2.3 自状态 SelfState（解决 buff/武器库/承诺）

```
SelfState {
  hp / stamina / 资源（技能层数、耐力、物品冷却）
  buffs / debuffs：类型桶向量（输出↑/机动↑/防御↑/控免/减速/持续伤害/治疗），各桶强度 0..1
  arsenal：武器库快照 [主手, 候选 1..N]（每把：类别、射程、派生可用性、冷却、风格适配）
  动画承诺（运行时读取，无需建模估算）：
    currentAnim {id, phase: PRE|ACTIVE|RECOVERY, remainTicks, cancellableAt, committedMotion}
    数据源：AnimationPlayer.getElapsedTime()/getTotalTime()（剩余帧）
            + AvalonAttackAnimation.getActivePhases(elapsed)（所在判定阶段）
            + patch.getEntityState()（INACTION/MOVEMENT_LOCKED/CAN_BASIC_ATTACK/CAN_SKILL_EXECUTION/LEVEL 1|2|3）
}
```

- 己方 buff/debuff 桶化而不是枚举（武器库/道具太多，桶化可泛化）；
- 动画承诺是**决策层的核心新输入**：模型知道自己"2 帧后到取消点，可以接闪避；12 帧后才落地，不能中途改"。

#### 3.2.4 空间感知 SpatialMap（解决障碍/流水/击退/钩爪）

```
局部栅格：半径 16 格、分辨率 2 格、约 8×8 桶（方向 × 距离）
  每桶标记：可达性（障碍/流水/岩浆/悬崖）、危险区（AOE 落点/弹道路径/持续伤害区）
位移事件：被击退/被拉近/被传送 → 事件总线 + "recentForcedMove" 状态位（10 tick 窗口）
```

- 栅格压缩：可达性直方图（哪个方向桶不可达）+ 危险区直方图，约 8~16 维；
- 战略层使用可达性做"绕行/撤出"决策；反应层用危险区做"AOE 规避"（跳劈落点登记后，若女仆在范围内且 WINDUP 后期 → 强制闪避出范围）。

#### 3.2.5 威胁评估 ThreatAssessment（可解释多维）

现在的威胁分（攻击中+2/危险+2/低血+1/近距+1）升级为多维向量，进入状态：

```
threat = {
  proximity  距离/射程威胁（含弹道 ETA）
  aggression 攻击频率/当前阶段（WINDUP 权重大于 ACTIVE——前摇是应对窗口）
  control    控制风险（有强控技能且接近释放条件）
  ranged     远程/放风筝威胁（远程武器 + 保持距离行为）
  buffed     增益强度（有输出 buff 的敌人更危险）
  hyperarmor 霸体（无法被打断 → 压制策略失效，威胁策略不同）
}
```

主目标选择 = 威胁分加权（含幽灵目标，但幽灵目标威胁折扣）；`selectPriorityTarget` 升级为多目标策略接口（战略层可指定"换目标"意图，模型可见 top-K 目标块）。

### 3.3 反应层详细设计（每 tick，规则优先）

反应层是**新架构的生存底线**，全部为确定性规则 + 每女仆常驻状态，**不依赖模型、不依赖 5 tick 节拍**。优先级从高到低：

1. **受控状态机**：`被击倒 → 倒地帧 → 起身选择`（默认起身闪避；若敌方 ACTIVE 阶段接近中 → 起身格挡；起身无敌帧内可再输入）。状态来源直接用内核 API：`patch.getEntityState().knockDown()`（`KnockdownAnimation` 绑定）＋ `StunType`（KNOCKDOWN / NEUTRALIZE / FALL / HOLD 各自映射恢复动作集）＋ `hurtLevel()`（受击硬直等级）；浮空/拉近/冰冻同理各自映射恢复动作集；
2. **前摇规避**：目标 `phase == WINDUP` 且 ①技能范围覆盖女仆当前位置/②WINDUP 剩余帧 < 女仆当前动画到取消点所需帧 → 按技能类型选择：`可弹反技能 → 弹反姿态`；`AOE 落地 → 朝范围外闪避`；`横扫 → 后撤闪避`；`无法应对 → 格挡`。**这是"跃起那一刻闪避"的实现位置**；WINDUP 数据来源见 3.2.1（EpicFight patch 敌方直接读 `getLevel()==1`，AV 系读 `EnemySkillDatabase`）；
3. **弹道拦截**：任一 Projectile `eta < 0.4s` 且即将命中 → 可格挡类：格挡/弹反；不可格挡：侧向闪避（方向 = 垂直弹道向量）；连续多弹 → 格挡优先（耐力保护）。**官方挂钩**：弹道命中前由 `EntityState.PROJECTILE_IMPACT_RESULT` 拦截（`DodgeAnimation` 已自带 `IGNORE_ALL_PROJECTILES`——闪避即弹道免疫，格挡/弹反窗口设置各自的 impact result）；
4. **打断保护 + 意图队列**：战术层意图到达时若当前动画处于"不可打断帧"（Commitment 目录判定）→ 意图经 `ServerAnimator.reserveAnimation` 挂起到动画结束点自动接续（见 3.6），而不是直接拒绝或强行覆盖动画；
5. **霸体命中感知**：命中事件后 1~2 tick 观测目标是否播放 `HitAnimation`（`hurtLevel()>0` 且 `StunType` 非 NONE）→ 更新目标记忆 `hyperarmor` 标志（观测 3 次无硬直 → 判霸体）；**DMC 系目标/武器额外接 `ICustomStunReceiver`**（`customStun` 协议，不走 EpicFight StunType）。

反应层与战术层的仲裁：**反应层事件（1~3）直接抢占**；意图队列只在非紧急时放行战术层意图。反应层行为的训练数据照常记录（标签 = 实际执行的动作），使模型在模仿学习中自然学会"这些窗口应该闪避/格挡"。

**闪避子系统规格**（参考实现三源交叉分析见 1.6，核心结论 1.6.5）：
- 伤害源分类表 `DamageClass`（DODGEABLE / BLOCKABLE / PARRYABLE / UNBLOCKABLE，按 `DODGEABLE_SOURCE_VALIDATOR` + `isBlockableSource` 双表构建）；决策顺序：UNBLOCKABLE（位移规避）> PARRYABLE（弹反）> DODGEABLE（闪避）> BLOCKABLE（格挡）；
- 阈值制资源化闪避：`结算后伤害 ≤ 阈值`（预知之眼式，默认 8，按护甲/韧性/附魔减免后计算）且资源充足 → 每 tick 自动闪避（无决策延迟）；高威胁保留资源；
- 闪避方向 = 灵动步伐算法（`dot`/`crossY` 前后左右，1.6.1）；闪避窗口 = `DodgeAnimation.delayTime`（0.6F≈12t 保护 + 碰撞盒缩放）；
- 攻击中拼刀兜底（刀光剑影：`penalty×impact` 耐力消耗、双方击退、取消伤害）——不可打断帧内唯一防守手段；
- 闪避成功事件：自建（`ATTACK_RESULT=MISSED` 挂钩，女仆无 `DodgeSuccessEvent`）→ 奖励 + "闪避反击宏"机会（天体圣刀式派生，1.6.4）。

### 3.4 战术层详细设计（RL）

#### 3.4.1 状态空间重设计

```
S = [基础态势 18 维（沿用，修正 s[0] 无目标=0.0、远目标=1.0 的表达）]
  + [目标表 top-K 块（每目标固定 12~16 维：距离/血量/护甲/阶段/威胁多维/霸体/置信度/弹道ETA）]
  + [自状态 12~16 维：hp/耐力/资源/buff桶×6/debuff桶×4/动画承诺（阶段+剩余帧+可取消）]
  + [空间 8~16 维：可达性直方图/危险区直方图/最近位移事件]
  + [历史帧：最近 4~8 个决策帧的（动作、目标距离、弹道ETA）——用拼接或轻量 GRU]
```

- 修正 s[0] 编码：无目标 = 0（而不是 1.0），距离单独通道，解决 V17 遗留的"空场与远目标混淆"；
- 目标表用固定 top-K 槽位（K=4~5，与用户设计"取前 5 个"一致），每个槽位语义固定（第 1 近/第 2 近……），**不随目标数漂移**；
- 若未来目标数超过 K，可升级为 set-encoder（对目标块做 pooling），但第一步用固定槽位足够。

#### 3.4.2 动作空间重设计（解决槽位漂移 + 多武器派生）

核心改动：**模型输出语义稳定，动态部分由宏解析器落地**。

```
动作空间（模型输出 64 维固定语义）：
  0   IDLE（待机/让行为表接管）
  1..8  通用战斗（剑圣攻击/枪神攻击/大招/JC/弹反/格挡/闪避/翻滚）
  9   切远程 / 10 切近战 / 11 轮换武器（带战略层候选）
  12..20  移动意图（前压/后撤/左绕/右绕/拉距/贴脸/撤出危险区）★新增
  21..30  防守技能（起身闪避/起身格挡/受控恢复）★新增
  31..63  技能宏槽：槽位按【稳定技能 id 排序】而不是按当前武器顺序
```

- **稳定技能 id**：`EfnSkillCatalog` 的每个技能在目录中有全局固定 id → 模型输出槽 i 永远代表"技能 id 排序第 i 的技能"，换武器后该技能不可用时掩码置零（现有掩码机制直接复用）。**彻底消除跨武器语义漂移**；
- **宏 = （武器选择 × 技能）组合**：战略层决定"切换到武器 W"，战术层决定"释放 W 的派生 D"——两者在意图队列里合并为宏；单条意图可表达"切阎魔刀 + 次元斩"两段式；
- **移动意图**是全新动作类：不直接播放动画，而是驱动 TLM 导航/寻路（`navigation.moveTo` + 方向向量），战术层第一次有了"空间策略"表达能力；
- 槽位超过 64 时的处理：技能按"当前武器优先 + 战略层候选武器"排序截断，**排序规则固定且不随时间变化**（模型可学习排序规律），掩码管理不变。

#### 3.4.3 模型结构

```
输入 S（~80~100 维，含历史帧拼接或 GRU 编码）
  → MLP 128-128（或 GRU(64) → MLP 64）
  → 双头输出：动作 logits(64) + 价值头 V(s)（1 维，critic）
```

- **加 critic**：这是训练侧最重要的单一改动——GAE 有了 baseline，优势估计方差大幅下降，离线数据也能做真正的策略优化；
- 保持 Java 端纯推理无依赖：推理器（`RlModel`）扩展支持 GRU 权重或退化为"历史帧拼接 + MLP"，推荐先做拼接（改动最小、效果已足够）；
- 模型文件格式向后兼容（加 critic 头 = 导出时多写一层权重，`RlModel` 加一个可选段）。

### 3.5 战略层详细设计（低频规则，逐步可学）

战略层每 ~20~40 tick 运行一次，输出低频修正，**覆盖/修正**战术层的长期倾向：

| 决策 | 输入 | 规则（初始，可逐步 RL 化） |
|---|---|---|
| 武器选择 | 目标类型/距离/霸体/己方资源/评分 | 远程放风筝 → 切远程/瞬移接近武器；霸体目标 → 高硬直需求武器；评分需求 → 轮换 + 切换连携 |
| 目标选择 | 威胁多维表（含幽灵目标） | 最高威胁非幽灵目标；幽灵目标追击代价 < 阈值时追击 |
| 资源管理 | 己方 buff/药水/冷却 | 战前预饮增益；低血且脱离攻击窗口 → 自愈（从 `StylishCombatSkill` 抽出，语义化） |
| 距离策略 | 目标类型/己方武器射程 | 近战武器 vs 远程敌人 → 拉距或突进二选一（交给战术层，战略层只给"倾向"） |
| 评分策略 | flair/切换计数/连段状态 | 低评分 → 优先"切换连携"宏；评分溢出 → 保守输出 |

战略层与行为表（`StylishBehaviorRegister` 的 EpicFight `CombatBehaviors`）的关系：**保留行为表作为 IDLE 时的自动连段/移动**，但把"行为表驱动的进攻"与"战略层/战术层驱动的进攻"统一到意图队列仲裁，避免现在 `arbitration=hybrid` 的双轨打架。

### 3.6 执行层：Commitment 目录 + 宏解析器

**Commitment 目录**（新增，扩展 `skills.json` 格式）：

```json
{
  "skills": {
    "yamato:judgement_cut": {
      "anim": "efn:biped/yamato/judgementcut_all",
      "commit": { "windupTicks": 8, "activeTicks": 10, "recoveryTicks": 14,
                  "cancelPoints": [ {"at": 6, "into": ["dodge","roll","parry"]} ],
                  "interruptibleFrames": "windup|early_active",
                  "motion": {"type":"none"}, "range": 3.0,
                  "needs": {"stamina": 0, "hyperarmor": false} }
    }
  }
}
```

- 每个技能声明：前摇/活性/后摇帧数、取消点（哪些帧可以取消进哪些动作）、位移承诺、射程、资源需求、命中是否带硬直/击飞/倒地（影响霸体判定）；
- **数据来源（本次重写的关键变化）**：不再依赖反编译提取帧信息。EFN/WOM 的技能动画在运行时就是 `AvalonAttackAnimation` 实例（`AnimationAccessor<? extends AvalonAttackAnimation>`），其 `phases`（`AvalonPhase(start, antic, preDelay, contact, recovery, end, ...)`，60 FPS 帧）与动画属性（`CANCELABLE_MOVE` / `NO_PHYSICS` / `NO_GRAVITY_TIME` / `MOVE_VERTICAL`）经 `AnimationManager` 拿到 accessor 后**直接反射读取**。`CommitmentCatalog` 在服务器启动/技能目录加载时构建缓存，字段映射：

| Avalon 运行时字段 | Commitment 字段 |
|---|---|
| `phase.start / antic / preDelay` | windupTicks（前摇；秒×20→tick） |
| `phase.preDelay..contact`（= EntityState.ATTACKING 区间） | activeTicks（判定窗） |
| `phase.contact..end / recovery` | recoveryTicks（后摇） |
| `phase.end` ＋ `AnimationPlayer.getTotalTime()` | 总帧数 / 剩余帧 |
| `CANCELABLE_MOVE`（Avalon 恒为 false）＋ INACTION 区间 | interruptibleFrames（**绝大多数帧不可打断是显式声明**） |
| `NO_PHYSICS` / `NO_GRAVITY_TIME` / `MOVE_VERTICAL` / `setMoveScale` | motion（位移/升空/无物理承诺） |
| `ATTACK_EVENTS` / `BE_ATTACK_EVENTS` | 命中/受击事件挂钩（弹反与霸体判定的直接数据源） |
| `phaseDamageMulti` / `phaseImpactMulti` / `phaseArmorNegationMulti` | 伤害/冲击/破甲倍率（技能价值评估） |
| `AttackPhaseProperty.STUN_TYPE`（`getEpicFightDamageSource` 读取） | 命中硬直类型 → 霸体判定输入 |

JSON 覆盖层的职责降级为：提取不到的技能给保守默认（前摇 6 帧/不可打断）＋ 逐武器人工校准覆盖 ＋ `EFN_SKILLS.md` 的按键/条件/派生树结构（技能树拓扑仍从反编译文档维护）。
- **反射双体系适配**：`SkillFrameReader`（替代单体的 `AvalonCommitmentReader`）支持两类来源——① Avalon 系（EFN/WOM 的 `AvalonAttackAnimation`，字段映射如上表）；② DMC MultiPhase 系（`com.dmc.invincible_dmc` 的 `MultiPhaseAttackAnimation` 等，大概率继承 EpicFight `AttackAnimation` 的 `phases` 字段，需反编译确认继承链后走同一 `getPhaseByTime` 读取，派生/硬直语义差异由 JSON 覆盖层校准）；两者的统一抽象为 `SkillFrameData {windup, active, recovery, cancelPoints, motion, stun}`；
- **意图队列实现机制（内核级捷径）**：利用 `ServerAnimator.reserveAnimation`——当前动画处于不可打断帧时，**不拒绝也不覆盖**，而是 `reserveAnimation(next)` 挂起；`ServerAnimator.tick()` 在当前动画自然结束时自动 `putOnPlayer` 接续播放。零轮询取消点、零竞态，且天然不触发 LinkAnimation 创建（维持 NPE 豁免的播放纪律，见 `docs/EFN_NPE豁免技术报告_20260823.md`）；`deadline` 超时的挂起意图直接丢弃并记录"意图过期"；
- **执行器改造**：`GenericCombatExecutor`/`EfnSkillExecutor`/`DefenseSkillExecutor` 的 `canExecute` 从"`inaction()` 一刀切"改为"查询 Commitment 目录：当前动画是否在取消点、新动作能否打断当前动画"（紧急动作 roll/dodge/parry 仍直放）；
- **宏解析器**（新增）：意图 = `{type: MACRO, macroId}` 或 `{type: MOVEMENT, dir}` 或 `{type: WEAPON, target}`；解析器负责查目录 → 播放动画 / 驱动导航 / 切换物品，并生成执行结果；
- **事件总线重设计**：从 Forge 广播总线改为"每女仆串行意图队列 + 优先级"（反应层 > 战术层 > 战略层），事件带 `deadline`（挂起最迟执行时刻，超时丢弃并记录"意图过期"反馈——这是新反馈维度）；Forge 事件保留用于跨模组兼容（`RlActEvent` 兼容旧监听器）。

### 3.7 反馈与奖励语义化

- **执行结果分级**：`EXECUTED / BUSY_IN_ANIM(剩余帧) / IN_COMMIT_WINDOW / NO_RESOURCE / OUT_OF_RANGE / INTENT_EXPIRED`——s[16]/s[17] 两位扩展为"最近执行结果的 one-hot 桶"（5~6 维），模型能区分"忙"与"无效"；
- **战斗事件**：命中/受击/控制/弹反/霸体命中 → 事件总线 → 奖励（训练）与状态（推理）双通道；
- **奖励语义化**（见 4.2）：把 20+ 条手工塑形收敛为少量可解释规则 + 稀疏主奖励，保留"评分/华丽度"为一级目标而不是熵约束。

### 3.8 方块武器设计（P5.5，仿 Him 克隆体，规则层）

**需求**：把 ItemCombat 的受击放方块格挡升级为 AV "Him克隆"式"主手方块 = 方块武器"体系——主手方块临时注册为方块武器，放置战技放出的方块 = 主手方块本身（圆石主手→速放圆石、深板岩主手→速放深板岩、黑曜石主手→黑曜石墙），且与克隆体一样**不消耗主手物品**。

**可行性结论（1.5.5 反编译佐证）**：AV 的方块武器是【专用物品 + EpicFight preset 类别 + CE 行为表 + 实体放置方法】的物品级静态注册；本项目泛化为**运行时检测 + 通用模板**，**无需逐个方块注册**（用户指定的圆石/深板岩/黑曜石三个注册项作为 per-block 覆盖，其余 BlockItem 全部走通用模板）。原因：放置的方块类型由主手 ItemStack 运行时决定，"武器规格"本身是模板；且无需改动 EpicFight 数据包注册表（EpicFight 无运行时动态注册 API，动态 mixin 返回 WeaponCapability 会破坏其按 ItemStack 的能力缓存，不采用）。

**实现**（全部规则层，RL 契约不变）：

| 模块 | 改动 | 说明 |
|---|---|---|
| `BlockWeaponRegistry`（新增） | `specOf(ItemStack)`：主手 BlockItem → 规格；`isHoldingBlockWeapon` | 规格 = 三级格挡冷却 + 放墙尺寸；`GENERIC` 通用模板（80/60/120t、墙 2×2）；`SPECIAL` 注册 COBBLESTONE / COBBLED_DEEPSLATE（通用规格）/ OBSIDIAN（墙冷却减半 40t，仿 Herobrine 暗影黑曜石积极放置） |
| `ItemCombat`（改造） | `tryPlaceBlockParry` 主手方块武器分支：三级策略优先用主手方块且**不消耗**（克隆体无限弹夹语义），冷却/墙尺寸取规格；无主手方块时回退原背包消耗逻辑 | 一级放墙 `placeWall` 参数化 rows/height（默认 2×2） |
| `ItemCombat`（新增） | `tryActiveBlockWall(maid, target)`：主手方块武器 + 目标 ≤3 格 + 墙冷却就绪 → 主动朝目标放墙（不消耗），临时方块照常 3t 自动移除 + SpatialMap 危险区登记 | 仿 `placeRandomFrontWall`/暗影黑曜石墙的**主动放置战技**；与受击墙共用冷却 |
| `StrategicLayer`（改造） | 方块武器判定前置：主手方块时**不参与武器轮换**（跳过 1a/1b/2 切武器规则），目标近身时优先调用主动放置战技 | 方块是武器，不轮换、不切远程 |
| `RlConfig`（新增开关） | `item_block_weapon = true` | 与 `item_block_parry` 独立开关；关闭后完全回退旧背包格挡逻辑 |

**约束保持**：临时方块 3t 自动移除（竞技场不污染地形）；动作不进 RL 动作空间（64 槽不变），只记录 `item_block_weapon_wall` / `item_wall_parry(block_weapon)` 等 trace 事件；训练契约（32 维状态 / 64 动作 / 槽位稳定）不受影响。

### 3.9 自适应战斗学习设计（P5.6，规则层）

**来源**：外部同类模组机制调研（反编译分析见内部文档 `docs/mimic_招式学习分析_20260825.md`，仅内部参考）。借鉴的是公开的通用游戏设计模式（经验驱动的招式调度），**未复制任何第三方代码**——外部模组为闭源（All Rights Reserved）且本模组需开源，2026-08-25 已做合规重构：全部实现为原创代码（数据结构和算法与外部实现不同），命名、注释、配置键、trace 事件均中性化（`adaptive_*`），发布代码中不含第三方引用。

**实现**（全部规则层，RL 契约 32 维/64 动作/槽位稳定不变）：

| 模块 | 机制 | 配置 |

| `CombatLibrary`（新增） | **敌方节奏统计（攻击间隔 EMA）**：观察目标攻击动画切换时刻，指数滑动平均估计连段间隔 → 连段中（距上次攻击 ≤1.5×平均间隔 且 连段计数 ≥2）/ 空窗（≥2×平均间隔）判定，随对手风格自适应；**命中经验（极坐标扇区桶）**：每次命中把"出招起点→目标位置"量化到（距离档 0~8 格 × 45° 角度扇区）桶（`recordHit`），出招前查桶（`canReach`）判定经验射程；**热度衰减调度**：自适应规则模式按 经验分（桶丰富度 + 当前可命中 + 空窗大技能加成）× 热度系数（越久未用越高、刚用过降权）排序自身武器技能库后播放；**增益窃取（时长截断）**：仅复制剩余时长 ≥100t 且不降级自身的 BENEFICIAL 效果 | `adaptive_learn=true` / `adaptive_hitgrid=true` / `buff_steal=auto`（auto=仅竞技场训练采集启用，加快训练速度；on/off 可选） |

| `RlActionRegistry`（改造） | `dispatch` 执行成功（EXECUTED）时记录出招起点（命中经验数据源） | — |
| `AutoArena`（改造） | `shadow_ai=model\|adaptive`（自适应影子女仆）；**自我博弈**：course.json `selfplay=true`（instructor 判定全面达标 balanced 时写入）→ 生成**自适应对手女仆**（规则 AI，与主女仆互相仇恨、女仆 vs 女仆），击杀/重生纳入胜率 | `arena.properties shadow_ai=model` / `selfplay=false` |
| `RlCommand`（新增） | `/rl adaptive` 状态查询 | — |

## 四、训练体系重写

### 4.1 从"离线清洗迭代"到"在线 RL + 影子评估"

```
生产服务器（竞技场 + 真实女仆 shadow 采集）
   │ 每 tick：决策（当前生产模型）→ 执行 → 轨迹(状态/动作/奖励/事件) → 队列
   ▼
学习器（异步，train/ 目录）：PPO（带 critic）或 AWR
   │ 批次学习 → 新模型候选
   ▼
影子评估（关键新增）：
   │ 竞技场女仆对半分 A/B：A 用生产模型，B 用候选模型
   │ 指标：胜率 / 受击率 / 华丽均值 / DPS / 资源利用率 / 决策延迟
   ▼
门禁通过 → 部署（现有 iterate.py 的 RCON /rl reload 保留）→ 监控 30 分钟 → 异常自动回滚到 prev_deployed
```

- **探索**：真机 ε 从 0.08 降到 0.02（在线循环里探索来自学习器的熵，而不是真机随机）；竞技场女仆保留 ε=0.1 采集多样性；
- **价值函数**：critic 头 + GAE(λ=0.95)，这是训练侧第一优先级；
- **影子评估不阻塞采集**：A/B 分流是部署门禁的输入，不是训练的前提；
- **回滚**：`iterate.py` 已有 `rl_model_prev_deployed_*.bin` 备份机制，补一个"部署后 30 分钟指标检查 → 自动回滚"脚本即可。

### 4.2 奖励函数重设计

原则：**稀疏主奖励定方向，少量结构化子奖励给梯度，删除对抗性塑形**。

```
主奖励（每轨迹稀疏）：
  +100 击杀；  -100 死亡；  -30 被击倒（保留，但只记一次）；  ±评分结算（战斗结束按 flair 结算一次）

结构化子奖励（每决策步，全部可解释）：
  +命中（按伤害量/距离系数，保留 30/10/2 但去掉"远程归零/连射衰减"等对抗性规则）
  +弹反成功 +50 / 格挡成功 +10（保留）
  +受控恢复及时（被控后首次正确恢复动作）+5
  +前摇规避成功（WINDUP 期间离开范围/闪避成功且未受击）+10
  +切换连携（切换武器后 10 tick 内命中）+15（★评分机制的直接建模）
  -空挥惩罚（无效意图过期/无目标攻击）-2（用新反馈维度 INTENT_EXPIRED/OUT_OF_RANGE）
```

**删除/降级**：熵奖励、滥用惩罚、远程衰减、贴脸指数惩罚——这些是"让模型显得多样"的约束，不是"打赢"的目标；它们的职责由"评分结算 + 切换连携奖励"接管（DMC 风格本来就是奖励信号，不是分布约束）。距离惩罚可以保留为弱项（-1/秒）防止纯放风筝，但强度降到原 1/10。

### 4.3 课程学习与环境脚本化对手

`AutoArena` 的对手从"固定 Boss 列表"升级为**可配置脚本对手**（arena.properties 扩展），按课程顺序解锁：

| 课程 | 对手脚本 | 解锁条件（上一课达标） |
|---|---|---|
| L1 基础近战 | 近战 Boss（现有） | 胜率 ≥ 60% |
| L2 不可打断/霸体 | **AngrySteve 原型**（永久眩晕免疫 + BurstProtect + 方块格挡 + 珍珠反击）：多段小伤害输出、骗方块、后摇窗口 | L1 达标且"单局伤害段数 ≥ 30"且"受击率 ≤ 阈值" |
| L3 远程放风筝/弹道 | **Null 原型**（飞行武器群 + 弹道免疫 + 概率弹反 + 凋零骷髅）：3D 幽灵目标、武器实体分流、弹反规避 | L2 达标且"弹道规避率 ≥ 70%" |
| L4 空间控制/拉近 | **Alex 原型**（钩枪 + 钓鱼竿 PULL/JESSICA 破防 + 放墙 + 岩浆桶）：被拉近事件反应、格挡/起身时限 | L3 达标且"受控位移反应事件触发率 ≥ 80%" |
| L5 混合团战 | 2~3 个不同课程对手同场（含读招机制：危险动画清单触发侧闪/逃跑） | 单挑各课达标 |

- 脚本对手用现有实体能力实现（annoyingvillagers 系 + 命令/行为注入），不引入新模组；
- 每课产出独立轨迹目录（`trajectories_l2` 等），训练时按课采样——**课程是数据组织方式，不是模型切换**（单一模型 + 课程数据混合比例调度）；
- 保留僵尸轨迹混合（10%）作为基础移动先验。

### 4.4 离线数据的新角色

`relabel.py`/`crucible.py`/`extract_melee.py` 不再作为训练主数据源，降级为：
- **BC 预热的辅助先验**（近战 npz 保留）；
- **回放增强（Replay）**：在线学习的经验池保留最近 N 万步，旧轨迹只用于 BC 预热，不进入策略优化主循环（避免分布污染）；
- 轨迹格式升级：头部加 `version + stateVersion`，`stateDim` 升级后旧轨迹可识别并丢弃（当前 16/18/32 混用是靠维度嗅探，容易踩坑——`train_ppo.py` 已经踩过一次，见 `--force-input-dim`）。

### 4.5 评估指标与部署门禁

```
在线指标（服务器每 5 分钟汇总）：
  竞技场女仆：胜率 / 平均战斗时长 / 受击率（次/秒）/ 华丽均值 / DPS / 动作熵（多样性，仅监控不优化）
  生产女仆（shadow 采样）：受击率 / 决策被拒率（BUSY 占比）/ 意图过期率 / 无目标发呆时长占比
门禁（候选模型上线条件）：
  ① 影子评估受击率 ≤ 生产模型 × 1.05
  ② 影子评估胜率 ≥ 生产模型 × 0.95
  ③ 决策被拒率 ≤ 20%（当前模型在长动画下被拒率大概率超标，这是修复效果的量化验证）
  ④ 无"维度不匹配"告警、无轨迹格式异常
```

## 附录 B：关键术语表

| 术语 | 含义 |
|---|---|
| Commitment（动作承诺） | 动作的时序元数据：前摇/活性/后摇帧、取消点、位移、射程、资源需求 |
| 幽灵目标（Ghost Target） | 脱锁后仍保留"最后位置+速度外推+置信度"的目标记忆 |
| 意图队列（Intent Queue） | 每女仆串行动作请求队列，带优先级与 deadline |
| 技能宏（Skill Macro） | 武器选择 × 武器内派生的组合动作，由宏解析器落地 |
| 受控状态机 | 被击倒/浮空/拉近等控制状态的恢复动作选择逻辑 |
| 影子评估（Shadow Eval） | 候选模型与生产模型 A/B 分流比较，作为部署门禁 |
| 课程学习（Curriculum） | 按对手复杂度逐级解锁的训练数据组织方式 |
| AvalonPhase | Avalon 攻击动画的判定阶段参数：start/antic/preDelay/contact/recovery/end（60 FPS 帧，`帧号/60F` 换算秒） |
| EntityState | EpicFight 帧级状态谱：INACTION / ATTACKING / MOVEMENT_LOCKED / TURNING_LOCKED / CAN_BASIC_ATTACK / CAN_SKILL_EXECUTION / HURT_LEVEL / KNOCKDOWN / PHASE_LEVEL 1\|2\|3（官方注释：1=前摇 2=攻击 3=后摇），由 `bindPhaseState` 按帧区间绑定 |
| StunType | EpicFight 硬直类型：NONE/SHORT/LONG/HOLD/KNOCKDOWN/NEUTRALIZE/FALL；`hasFixedStunTime()` 区分固定/可变硬直时长 |
| reserveAnimation | `ServerAnimator` 的挂起机制：当前动画自然结束后自动接续播放目标动画（意图队列零轮询挂起的基础） |
| CANCELABLE_MOVE | EpicFight 动作属性：BasicAttackAnimation 默认 true（可取消移动）；Avalon/EFN 系显式置 false = "不可打断"约定的来源 |
| SkillFrameData | 双体系统一帧数据结构：{windup, active, recovery, cancelPoints, motion, stun}（3.6） |
| BurstProtect | AV 爆发伤害保护：单次伤害 cap（AngrySteve 5% / Alex 15% 最大生命）+ 短窗口累计衰减 + 连击保底，受击动画中忽略 |
| Guard Break / 处决 | CombatEvolution 机制：目标破防（GUARD_BREAK 动画）或倒地后，敌方 4 格内可触发处决连段（ExecutionAttackAnimation） |
| 危险动画清单 | `EscapeUtil.DANGEROUS_ANIMATIONS`：AV 识别的跨模组大技能列表（WOM 30+ / EFN），播放时敌方侧闪/逃跑 |
| DodgeAnimation | EpicFight 闪避动画：`delayTime`=保护窗（INACTION+移动锁）、`width/height`=碰撞盒缩放、`ATTACK_RESULT`=可闪避伤害源 MISS、`PROJECTILE_IMPACT_RESULT`=弹道免疫、`BYPASS_DODGE` 标签豁免 |
| 预知之眼（Eye of Precognition） | epicmoonmod 双刀资源系统：60t 恢复 1 层（上限 30）；弹反/闪避成功耗 1 层→"加速未来"；自动闪避耗 3 层（结算伤害 ≤ 阈值 8） |
| DamageClass | 伤害源分类：DODGEABLE / BLOCKABLE / PARRYABLE / UNBLOCKABLE（闪避决策顺序依据，1.6.5） |
