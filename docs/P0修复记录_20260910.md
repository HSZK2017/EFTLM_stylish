## 1. 逐项修复

### P0-1 幽灵目标机制是死代码（`rl/TargetTracker.java`）

**旧行为**：`update()` 用 `ghost` 标志当"本帧已扫到"的代理，而 `ghost` 只能由被同一分支挡住的 `onNotSeen()` 置位 → `ghost` 恒 `false`、`confidence` 恒 `1.0`：幽灵化、置信度衰减、位置外推全部不可达；脱锁目标永久驻留，陈旧 `distance/attacking/phase` 每 tick 被写回 `ATTACK_TARGET`。

**新行为**：
- "本帧是否扫到"改用 `t.lastSeenTick == tick` 判定，`onNotSeen(maid, tick)` 可达；
- `onNotSeen` 里把两种时间语义分开：**置信度**按距上次真实看到的 tick 数衰减（`GHOST_DECAY^missed`，单次调用补偿全部漏扫）；**位置**每调用一次只前进一个速度步（该方法每 tick 调用一次），旧实现用 `dt` 步会在同一段脱锁时间里重复外推（1+2+3…）；
- 新增 `lastSeenPos` 锚点，外推总漂移限制在 `SCAN_RANGE`（32 格）内，防速度噪声把预测点甩飞；
- 幽灵距离改为"女仆当前位置 → 外推位置"实时计算（旧实现只增不减）；
- `RlBrain.tick` 增加 `GHOST_LOCK_MIN_CONFIDENCE = 0.5`：置信度低于该值的幽灵目标只参与威胁评估/位置预测，**不再写回 TLM brain 的 `ATTACK_TARGET`**（否则女仆会追着外推位置空跑，同时让"无目标降级待机"约束失效）。

**验证**：编译通过；逻辑路径已按 `update()` 的调用序逐行复核（扫描 → 未扫到者 `onNotSeen` → `removeIf(confidence<=0.1)`）。
**观测**：trace 中应开始出现"目标脱锁后 confidence 下降、约 114 tick（≈5.7s）后被遗忘"；`/rl dump` 的 `tdist` 不再固定为陈旧值。

### P0-2 奖励与动作错位一步（`rl/RlDataRecorder.java`、`rl/RlBrain.java`、`rl/RlFeedback.java`、`train/traj_io.py`）

**旧行为**：`recordStep` 把"上次决策以来累计的奖励"写进本步 → `rewards[i]` 实为 `actions[i-1]` 的后果，而 `gae_returns` 按 `actions[t]` 的后果消费；且塑形奖励（决策点同步写入）与事件奖励（滞后写入）**混在同一累加器**，偏移量随来源不同而不同。

**新行为**（轨迹格式升 **v3**）：
- 两个累加器分离：`PENDING`（**后果**奖励，命中/击杀/受击/弹反/切换连携…）与 `PENDING_STEP`（**本步塑形**奖励，熵/衰减/防守/距离/熔断/无效动作惩罚）；
- `recordStep`：先把 `PENDING` 回填到**上一步**，再将 `PENDING_STEP` 记在**新写入的这一步** → `rewards[i]` 与 `actions[i]` 严格对齐，与训练侧 GAE 假设一致；
- `flush`/`forgetMaid` 的尾步信用分配同时吸收两个池（最后一步动作的后果仍归最后一步）；
- `RlBrain` 5 个塑形函数、`RlFeedback` 的 `-2`、`AutoSkill` 的突进先验改用 `addStepReward`；`StylishCombatSkill`/`AutoSkill` 的事件奖励保持 `addReward`（语义不变，落点变正确）；
  最终落点审计（编译后 grep 全量调用点，共 20 处）：
  - **后果池 `addReward`（8 处，全部在 `StylishCombatSkill` 事件回调）**：击倒 −30、切换连携 +15、命中 +30/+10/+2、突进 +50、击杀 +100、弹反 +50、受击 −30；
  - **本步池 `addStepReward`（12 处）**：`RlBrain` 熵/衰减/防守/距离/熔断 10 处、`RlFeedback` 无效动作 −2、`AutoSkill` 突进先验 +10；
- `train/traj_io.py`（**新增，唯一轨迹读取实现**）对 v1/v2 旧数据做一步平移补偿：`r_new[i] = r_old[i+1]`、末步保留，并在 `Trajectory.legacy_reward_shifted` 标记；5 个训练脚本改为共用该实现，顺手统一了原先强度不一的边界校验（`n/sd/na` 上限、动作越界过滤）。

**近似说明（必须知道）**：旧格式里塑形与后果混在一起，无法无损分离。平移后的误差 = `塑形(a[i]) − 塑形(a[i+1])`，量级远小于主奖励（命中 +30 / 击杀 +100 / 受击 −30）。**v3 新数据无此误差**，随部署推进旧数据占比自然下降。

**验证**（`train/selftest_p0.py`，16 项断言全通过）：
- v2 文件 `[10,-3,5,100]` → 载入为 `[-3,5,100,100]` 且 `legacy_shifted=True`；标签不随奖励平移；
- v3 文件奖励原样、`legacy_shifted=False`；
- 截断/空文件 → `None`（不抛异常）；
- npz 载入：越界动作过滤（5→3）、18→32 维补零、权重归一化到均值 1、缺失键返回 `None`。
