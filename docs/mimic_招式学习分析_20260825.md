## 2. 核心机制反编译解析

### 2.1 招式学习（"观察并复刻每一次攻击"的真实实现）

`MimicPatch.tick` 每 tick 扫描 30 格内所有存活 LivingEntity → `tryToLearnAnimation(entity)`：

```
1. 取目标 EpicFight patch，要求 HumanoidArmature（人形骨骼）
2. 偷 buff：目标所有 BENEFICIAL 药水效果复制给自己（m_7292_）
3. 读目标当前动画：
   - 是 AttackAnimation 且（主/副手是 Avalon 动画物品 或 动画注册名含 "wom"）
     → 不学（"太强的招式学不会"），回 3 HP，随机嘲讽玩家（tip_1/2/3）
   - 否则（普通武器）且 主手非空：
     动画总时长 < 8.0 秒 → copyMap.put(动画, 新 CopyAnimationInfo(动画, 主手, 副手))
```

关键事实：
- **学习条件**：攻击动画 + 人形骨骼 + 时长 <8s + 非 Avalon/wom 高级动画。时长上限防学大招，高级动画黑名单防复制不可控招式。
- **去重**：`copyMap` 以动画 accessor 为 key——同一招式只学一次（但每次释放都更新命中网格）。
- **无上限**：`copyMap` 是普通 HashMap，无容量上限——"学习无上限"属实，但 `playCopyAnimation` 中 `copyMap.size() > 15` 后每次出招随机把库中旧招塞入连招缓冲（"不断深化理解"的实现）。
- **持久化**：`CopyAnimationInfo.savaInTag/loadFormTag`（动画注册名、使用次数、命中网格 x/z 列表、主副手物品 NBT）；实体 `saveCopy/loadCopy` 存整个库；Proteus 死亡掉落"推荐信"物品携带 copy_info → 玩家可在遗忘之海外使用召唤记录的战斗虚影。

### 2.2 命中网格经验（"分析出招时机"的真实实现）

每个 CopyAnimationInfo 维护 `List<Rectangle>`（局部坐标整数格，以自身朝向为参照系）：

```
addRectangle(startPos, startYRot, targetPos)：   // MimicPatch.attack() 命中回调时调用
  把 "释放动画时的自身位置 → 目标位置" 的水平向量旋转到自身朝向坐标系，
  取整为 (gridX, gridZ)，去重后加入矩形列表
```

```
checkCanHit()：                                 // 出招前判定
  目标当前位置（同样旋转到局部坐标，Y 差 ≤2）
  ∈ 任一已记录网格 → 该招式"现在放能打中"
```

**本质**：每个复刻招式带一份"用该招命中过什么相对位置"的经验表——出招前先查表，只放"历史命中过的相对位置能覆盖当前目标"的招式。这是**招式的价值/射程学习**：空挥积累经验（`PLAY_RANDOM_COPY_WITHOUT_HIT` 专找"打不中"的招式放，用 miss 换经验），命中后网格更新，越打越准。

### 2.3 连招构建（"构建流畅且极具毁灭性的独创连招"的真实实现）

`playCopyAnimation(info)`（唯一出招入口）：

```
1. 当前动画若是 LinkAnimation（过渡中）→ 跳过（不打断）
2. copyMap.size() > 15 → 随机塞一个库中旧招进 comboList（旧招复活）
3. comboList.size() < 5 → 新招（去重）入队并播放    // 按学习顺序构建连招链
4. comboList.size() >= 5 → 按 combo 索引循环播放 comboList[combo]，
   播满 5 段后 combo 归零、comboList 清空               // 五连段循环
```

**本质**：连招链 = 最近学到的 5 个招式（去重）按学习顺序组成，满 5 段后循环，5 段播完清空重来（新招优先）。连招不是预设的，而是"学习顺序"的直接产物——战斗越久，链上招式越新。

### 2.4 出招决策（行为表调度）

`MimicCombatBehaviors`（Avalon 行为系统）定义多个 BehaviorSeries（连段链），每个系列 = 一串固定顺序的 Behavior（5~11 段），段间以权重/冷却/TargetInGirdCondition（目标在矩形网格内才触发）调度：

- PHASE1：开局/收尾 = 自身 SKILL_1 动画（带 TargetInGirdCondition 5×5 或 20×20 网格条件），中间穿插 3~5 个 `PLAY_RANDOM_COPY_WITHOUT_HIT` / `PLAY_CAN_HIT_COPY` / `TRY_PLAY_COMBO`。
- PHASE3：更激进（权重 500），SKILL_3 开场/收尾 + 更多连招段。
- `PLAY_CAN_HIT_COPY`（能命中才放）与 `PLAY_RANDOM_COPY_WITHOUT_HIT`（打不中也要放，积累经验）交替——**探索/利用共存**。

### 2.5 战斗数值设计（学习深度的双刃剑）

| 机制 | 实现 | 效果 |
|---|---|---|
| 盾条 stunShield | 100（Proteus 150）；有盾免疫硬直（applyStun 返回 false）、受击动画返回 null、伤害×0.3；盾碎后 100t 恢复 | 有盾期霸体 + 减伤，无盾期脆 |
| 受击保护 | protectTick=35 内连续受击逐次减伤 15%，最高 90% | 防连段秒杀，逼玩家抓窗口 |
| 单发伤害 cap | 每次受伤 amount > 30 → 30 | 同上 |
| **学习-伤害权衡** | 受伤倍率 = min(copyMap.size()×0.8, 1.5)；攻击命中回血 = damage×min(0.1+size×0.1, 1.0) | **学得越多，自己越疼但回得越多**——鼓励速杀 vs 越拖越强的张力 |
| 增益窃取 | 每 tick 复制目标全部 BENEFICIAL 效果 | 敌方 buff 即我方 buff |

### 2.6 传播与阶段

- Proteus 半血：召唤 2 个 ShadowMimicEntity，各加载一份**当前学习库快照**（loadCopy）——分身共享学习；虚影命中给主人回血 30%。
- 虚影全灭 → 盾 1e8 → 阶段 3（行为表换 PHASE3）。
- Proteus 之间：低血者把 copy 传给高血者后自灭（tickNearbyEntity）——**学习库可转移/聚合**。

## 4. 可借鉴性评估（结论：**可借鉴，全部可落在规则层，RL 契约不变**）

### 4.1 直接可借鉴（低风险，规则层实现）

**① 动态招式库（CopyLibrary）——"女仆观察敌方动画学招式"**
- 落点：`StylishCombatSkill.MaidTick`（已有事件挂钩）或新增 `CombatLibrary`（类似 `BlockWeaponRegistry` 的注册表类）。
- 机制：战斗模式女仆每 tick 扫描目标（AV NPC）当前动画；是 `AttackAnimation` 且时长 <8s 且非白名单（Avalon/wom 专属动画）→ 加入女仆的"影子招式库"（按动画 accessor 去重）。
- 与本模组结合点：**技能槽语义不变**（slot_stable 保持：槽位=技能身份+掩码），动态库招式作为**技能候选池的补充来源**（RL 掩码按库内技能开放）；`skills.json` 静态 392 技能保留为底座。课程模式（course.json 换敌人）下女仆学到的招式库随敌人变化——天然课程化。
- 风险控制：训练契约不变（32 维状态 / 64 动作 / Java 模型格式）；动态招式只影响**哪些槽可用**（掩码），不改变布局。

**② 命中网格经验（HitGrid）——"招式的实际射程/时机经验"**
- 落点：扩展 `CommitmentCatalog`（每个 SkillFrameData 附带 `HitGrid`：局部坐标网格列表）；`RlBrain` 决策前或 `RlActionRegistry.canExecute` 过滤"当前目标不在任何历史命中网格"的招式。
- 机制：`GenericCombatExecutor`/`EfnSkillExecutor` 命中回调（已有命中事件）时，把"出招时自身位置→目标位置"旋转进自身朝向坐标系取整入网格（照搬 `CopyAnimationInfo.addRectangle/checkCanHit` 的数学）。
- 价值：比 Commitment 静态 range 更准——学到的是**对当前对手的实际命中分布**（AV NPC 的移动习惯），RL 掩码更精准 → 减少无效出招（现 rejected_rate 高达 80%，0.95 在最新课程中）。
- 注意：`MimicPatch.attack` 的网格记录点（出招起点 + 命中点）与我们的 `animationStartPos` 对应物 = CommitmentCatalog 出招时记录自身位置即可。

**③ 连招链缓冲（ComboChainBuffer）——"学习顺序成链，满段循环"**
- 落点：`StrategicLayer`（40t 规则）或 `StylishCombatSkill` 连段计数处。
- 机制：按当前武器维护最近 N（5）段已执行技能；满 5 段后循环播放该链（配合现有 switch_combo +15 奖励）。mimic 的"copyMap>15 随机插入旧招"对应我们的"低华丽度时从武器技能库随机插入旧招"（与现有 FLAIR_SWAP_TRIGGER 逻辑同构）。
- 价值：连招显式化、可观测（trace 事件），且与 RL 并存（RL 选招式时优先选缓冲链下一段，缺失则 RL 自由选择）。

**④ 增益窃取（buff steal）**
- 落点：影子女仆（A/B 评估场景）或竞技场女仆对 AV 目标——目标有 BENEFICIAL 效果时复制给自己（限 1 个目标，节流）。
- 价值：PVE 对 AV 系（它们有大量 buff）的直接收益；PVP 影子评估对照时体现"学习型对手"特性。

**⑤ 影子评估扩展：mimic 模式 vs RL 模式**
- 落点：`AutoArena` 双女仆影子评估（已有 shadow_model_file 机制）。
- 机制：新增 `shadow_ai=mimic` 配置——影子女仆启用 mimic 式规则 AI（动态学习 + 命中网格 + 连招缓冲），主女仆走 RL 模型。**A/B 直接对比"学习型规则 AI"与"RL"的胜率**——这是对本模组 RL 价值最直接的验证实验，也贴合"战斗越久越强"的课程语义。

### 4.2 需适配（可行但有约束）

**⑥ 无上限学习 ↔ 64 槽固定**：不能直接照搬无上限。适配：动态库按武器分池 + LRU 淘汰（库 > 阈值时淘汰使用次数最少者），槽位掩码只开放前 K 个；或学习库仅用于**训练数据增强**（库中招式执行轨迹标记 `copied` 标签，train_ppo 的 label remap 支持新标签）。

**⑦ 行为表 BehaviorSeries 顺序连段**：本模组用 EpicFight `CombatBehaviors`（单 Behavior 随机权重，`StylishBehaviorRegister`）；mimic 的系列化连段需 Avalon 行为框架（额外依赖）。不引入新依赖，用 **RL 缓冲 + StrategicLayer 规则** 表达同等语义（④③）。

### 4.3 不适用 / 不建议

**⑧ "学习 = 伤害倍率增长" 权衡**：本模组是 PVE 训练环境（女仆 vs AV NPC），不需要"越学越疼"的玩家博弈设计；受击保护/单发 cap 是 boss 设计，与本模组无关。
**⑨ 偷取玩家提示语（tip）与回血嘲讽**：PVE 无意义。
**⑩ PlayerShadowMimic（关闭学习）**：与我们的影子评估目的相反（我们要的是"会学习的影子"）。

## 5. 建议实现方案（规则层，分三步，RL 契约全程不变）

| 步骤 | 内容 | 文件 | 验证 |
|---|---|---|---|
| A | `CombatLibrary`：动态招式库（学习条件照抄：AttackAnimation + 时长<8s + 白名单过滤 + 去重）+ trace 事件 `copy_learn` | 新增 `rl/CombatLibrary.java`；`StylishCombatSkill.MaidTick` 挂钩 | `/rl library` 查询命令（新增）；trace 观测 |
| B | `HitGrid`：CommitmentCatalog 附带命中网格 + 命中回调记录 + 决策掩码过滤（RL 与规则层共用） | `CommitmentCatalog` / `RlActionRegistry` / 执行器命中回调 | trace 观测 `hitgrid_*`；rejected_rate 对比 |
| C | `ComboChainBuffer`（5 段循环 + 旧招插入）+ 影子 mimic 模式（`shadow_ai=mimic`） | `StrategicLayer` / `AutoArena` / `RlConfig` | `/arena stats` A/B 胜率对比 |

风险清单：训练契约（32/64/槽位）不变；动态库不参与训练标签（避免轨迹语义漂移）；HitGrid 只在模型掩码层生效（推理期，不进 32 维状态，避免状态漂移）；影子 mimic 模式仅在 shadow maid 生效（不影响主训练数据流）。

## 6. 结论

Mimic 的"招式学习/连招创建"并非宣传中的"无上限学习算法"，而是三件朴素且有效的工程：
1. **运行时观察学习**（敌方 AttackAnimation → 去重入库，白名单 + 时长过滤）；
2. **命中网格经验**（每招记录历史命中相对位置，出招前查表——招式的经验射程）；
3. **学习顺序成链**（最近 5 招组成连招缓冲循环播放，>15 招后旧招随机复活）。

三者**全部可借鉴到本模组且均落在规则层**：动态招式库补强技能候选池（课程化），命中网格解决 rejected_rate 80%+ 的无效出招问题，连招链缓冲显式化连招并配合切换连携奖励，增益窃取与"mimic 影子模式"则直接服务于 P4 影子评估的 A/B 对照。唯一需要改造的是"无上限"→ 64 槽约束下的 LRU 池化。不建议照搬的是 boss 数值权衡（受击保护/伤害倍率）与玩家博弈设计。
